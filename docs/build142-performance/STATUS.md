# Build 14.2 performance work

Base: `a22bd57b51881dec0278dc9a451a2a13103a7fd7`, physically validated Build 14.1. Reference: Build 15 `bf58e95d8303e9af49f510659bac280821428041`.

Selectively transferred bounded byte-exact audit evidence, session actor lifetime, indexed Unicode substring searches, authenticated form preparation, draft de-duplication and export I/O. Backup picker, Open In route, portable format, Bundle ID and Keychain identifiers remain from 14.1. The 14.1 period-specific historical stock correction is preserved explicitly.

New invalidation events follow verified persistent writes only, contain mode/revision/kind only, and require an authenticated read by every consumer. Retained History tabs recheck authenticated revisions when active; data refresh preserves filters and pagination. Changed workers invalidate roster reuse; disk authentication runs on every recovery, including cache hits. A failed write emits no update.

Build 15 evidence is prior research, not a Build 14.2 performance result. Its Core/native approvals do not constitute complete UI approval. Build 14.2 runs fresh directed/full Core, Excel, native, UI and cross-version encrypted compatibility checks. The same-run Linux Release comparison uses 9,648 synthetic workers and 1,005 visits; its timings and process RSS are not iPhone measurements. No physical performance claim is made before the user tests the candidate.

Alert projection is built from the same authenticated recovery as Home counters: drafts after 60 minutes without editing, verified expiry warnings from 30 days, expiry-day notices, and known zero stock. Local scheduling reconciles stable identifiers, cancels pending/delivered resolved events, respects mode separation and permission denial, uses generic lock-screen content and caps the planned queue. Restored drafts retain their original last-edit deadline. In-app alerts display authenticated product descriptions only after session authorization. No new clinical fields or backup schema changes are introduced.

Minimum stock thresholds have no authenticated source field; low but positive stock is not guessed. Occupational follow-up, EMO and reinstatement dates have no authenticated model in the base and remain pending verified source data. The app cannot evaluate changed events while fully closed: previously scheduled triggers fire locally and reconciliation runs after opening, authorization and verified writes. Permission denial does not hide in-app alerts.
