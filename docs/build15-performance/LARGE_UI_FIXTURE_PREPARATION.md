# Larger native/UI fixture — preparation only, not execution evidence

The existing same-host Core workloads already test9648workers and1005visits, while the coordinated UI capture first validates its synchronization using the original two-worker fixture. A source-only native test fixture is prepared separately to extend actual SwiftUI coverage to the large fictional workload after that recording protocol is validated.

N2LargeRosterProfileFixture is restricted to Simulator and the DEMO actor. It refuses an existing demonstration rather than replacing it; generates only invented workers/visits from the frozen synthetic resource; authenticates a demo-domain encrypted archive through the existing restore API; and asserts9648workers/1005visits. The existing two native helpers then activate their standard v2 physical counts and retain their original draft. Additional before/after checks compare every worker, every original visit and the entire physical inventory JSON; require the confirmed allergy and preservation of the existing encrypted draft. No real clinical namespace is accessed and no production file or user flow changes.

This fixture is not part of the primary4daba source or its29native/14UI approval. It has NOT been compiled or executed yet. A diagnostic workflow must build the test target, create its own new Simulator, run seed/baseline/after cases around real UI actions and retain actual results. It cannot be counted as passed based on code inspection, appended to the official native count, or used to authorize an IPA. All worker/clinical fields remain fictional; no real iPhone data or backup is used.
